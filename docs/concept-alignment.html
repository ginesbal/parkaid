Getting the Spline pin into the app

The app loads the code export, https://prod.spline.design/Q7HUDttDfqjuFFop/scene.splinecode, with @splinetool/runtime. The .spline file is editor source and cannot be loaded by the app. On iOS and Android a WebView runs a 20-line HTML page that loads the runtime; on web the same runtime draws straight into a canvas. A still PNG sits underneath for loading, offline and reduced motion.

Re-export before anything else. The current export is WebGPU only. Loading it logs This scene was exported for WebGPU only ... Re-export with renderer "Both" or "WebGL 2". Many phone WebViews do not have WebGPU, and there the pin would be blank. In Spline, export again with renderer Both, and keep the same URL.

The export also needs runtime 2.0.85 or newer; 2.0.75 refuses it as too new. The export carries the custom motion: loaded with runtime 2.0.85, the pin, Scene Root and Free Badge all move over time. For the icon-only Welcome, the page hides ParkAid Map Tile and ParkAid Map Streets after load().

Integration plan

Each step is one commit that leaves the app working. Motion uses React Native's built-in Animated, which the app already uses everywhere. New dependencies: react-native-webview for phones and @splinetool/runtime for web.

  1. Lock the Spline source and export assets

    • Re-export the code export with renderer Both. Keep Q7HUDttDfqjuFFop as the URL.
    • Keep the scene background at #F7F8FA. The app takes that value, not the other way round.
    • Export a transparent pin PNG at 1x, 2x, 3x and a small marker pin into mobile/src/utils/assets/brand/.
    • Regenerate icon.png, adaptive-icon.png, splash.png; set splash and adaptive backgrounds in app.config.js to #F7F8FA (now #001d4a) so launch flows into Welcome without a flash.
    Done when the assets are committed and the app icon shows the pin.

  2. Add tokens for the ink canvas and motion

    • Change TOKENS.bg from #F6F8FA to #F7F8FA to match the Spline background. One RGB step, invisible on its own, and every pin still blends in.
    • Darken textLight / textFaint from #90A0B0 (2.7:1 on white) to #647486 (4.8:1). Placeholders and hints then pass WCAG AA.
    • Add TOKENS.inkSurface, inkMuted, a TYPOGRAPHY.hero step (28/32, 700) and a MOTION object.
    • MOTION holds three durations (180, 240, 320 ms), Easing.out(Easing.exp), and the sheet's existing spring (tension 68, friction 9) so every screen springs alike.
    • Existing token names stay.
    Done when npm test passes and placeholders read clearly.

  3. Build BrandPin3D

    • npx expo install react-native-webview.
    • components/BrandPin3D/index.js: PNG underneath, WebView on top with source={{ html }}. The HTML imports @splinetool/runtime@2.0.85 and calls new Application(canvas).load(SCENE_URL). Background #F7F8FA, scrolling off, opacity 0 until the page posts ready, then a 240 ms fade.
    • index.web.js: the same runtime on a canvas, with no WebView. Same file split as MapScreen/index.web.js. Add @splinetool/runtime as a dependency for web.
    • Check AccessibilityInfo.isReduceMotionEnabled(); when true, or on onError, show only the PNG.
    Done when the pin animates on a phone and on web, and airplane mode shows the still.

  4. Add the Welcome screen and a root stack

    • Wrap the tab navigator in a native stack in App.js: Welcome, Tabs, later Details.
    • Read parkaid.welcomed from AsyncStorage to choose the initial route. Write it on "Explore parking".
    • Entrance: headline and body fade and rise 12px with a 60 ms stagger. The pin carries the moment; nothing else loops.
    Done when a fresh install shows Welcome once and the next launch opens Home.

  5. Refine Home you write: greeting rule

    • Replace LocationSection and QuickInfoBar with greeting + static pin, a search row that navigates to Map with search focused, and three chips.
    • Top pick card from the first spot, with a thumbnail and "View parking". Remaining spots render through a quieter ParkingListItem.
    • Keep the status banner, pull to refresh, empty and loading states.
    • The greeting rule (which hours read morning, afternoon, evening, late) is a small product call worth your own 5 to 10 lines.
    Done when Home matches the mockup with live data and every chip changes the list.

  6. Refine Map

    • Swap default markers for the exported pin image. Selected marker springs to 1.25 with the shared spring.
    • Peek header: "Parking around you", a count line, the top pick, a "View parking" button. Leave the gesture and snap code alone.
    • Marker tap and "View parking" navigate to Details.
    • Retake map-screenshot.jpg so the web preview stops showing the orange theme.
    Done when drag, flick and tap behave as before and markers read as the brand pin.

  7. Add Details, then delete the flip card

    • screens/DetailsScreen/index.js on the ink canvas, using the formatting already in cardHelpers.js.
    • "Start session" calls navigate('Park', { spot }); SessionScreen prefills rate and place from the param.
    • Delete FlippableParkingCard.js and cardStyles.js once nothing imports them. Net change should be fewer lines.
    Done when map, Details and Park connect end to end and the flip card is gone.

  8. Restyle the Session screen

    • Ink background, white TimerCard, "Active demo" badge from StatusBadge, progress bar animated with scaleX on the native driver.
    • Extend +30 min primary, End session secondary white. Time turns TOKENS.warning in the last 5 minutes.
    • Empty state keeps SetupCard with the static pin above it. Tab bar Park icon becomes the P glyph.
    Done when start, extend, expire and end all work and the screen matches the mockup.

  9. Motion and quality pass

    • Reduce motion on: no entrance motion, PNG pin, instant sheet snaps.
    • Test the WebView on one low-end Android device. If it stutters, fall back to the PNG there.
    • Run the Impeccable detector on changed files, then refresh README and case study screenshots.
    Done when tests pass, npm run export:web builds, and screenshots are current.

2. Which scene ships

The published page and the local file run different motion scripts. The code export is a third copy.

Recommended: re-export from the file you consider final, with renderer Both.

3. Chip meaning

The API filters by type (on_street, off_street, residential). "Near me" and "Best value" are sorts, not types.

Recommended: Near me sorts by distance, Best value by price on the client, Covered maps to off_street. Permit moves into Filters.

4. Ink canvas

The concept puts Details and Session on #0F1A26. The app is otherwise light-first.

Recommended: keep it. These two screens are focus moments, and the contrast marks them.

Impeccable critique

Two independent reviews of the five screens: a design review, and the Impeccable detector with measured renders. Score 20/40, Acceptable. The flow and restraint are right; the money moments are not designed yet.

  1. P1 Start session commits blind. No duration, total, zone or plate check at the tap that costs money. Add a duration stepper and a summary line, capped at the spot's max_time.
  2. P1 No protection when time runs out. The 5 minute warning equals the walk back and is colour only. Extend shows no price and ignores the 2 hour maximum. End sits 12pt under Extend.
  3. P1 Map is not glanceable. Identical unlabeled pins. Put prices on pins and tie the selected pin to the sheet card.
  4. P2 Touch targets and drift. Chips 34.8pt, Home "View parking" 39.3pt, back row 22.7pt, all under 44pt. Home and Map use different chips.
  5. P2 Calgary facts. Stephen Avenue is 8 Ave SW and a daytime pedestrian mall. Use a real on-street block, with its zone from zone_info.parking_zone.

The detector's 73 findings were 70 false positives (it mixes the page's dark and light theme colours) and 3 low-contrast amber tags on this page, not in the app. Three Map rendering bugs it surfaced (hidden tab bar, hidden location dot, misaligned edge) are fixed in the screens above.

Not changing

Backend, API contract, useParkingSpots, useLocationManager, session timing logic, the bottom sheet's gesture math, and the logger calls. The plan is UI only.
